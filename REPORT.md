## 1. Пояснення до коду

1. **Ініціалізація додатку та БД (`app.py`, `init_db`):**
   * Створено веб-додаток на мікрофреймворку **Flask** (`app = Flask(...)`) та підключено реляційну базу даних **SQLite** (`travel_planner.db`).
   * Функція `init_db()` автоматично створює таблицю `trips` із полями `id` (первинний ключ), `destination` (пункт призначення), `travel_date` (дата подорожі), `notes` (примітки) та `done` (статус виконання: `0` або `1`).
2. **Маршрутизація (Routing):**
   * `@app.route('/')` (`index`) — виконує SQL-запит `SELECT` для отримання всіх запланованих подорожей і передає їх у HTML-шаблон `index.html`.
   * `@app.route('/add', methods=['POST'])` (`add_trip`) — приймає дані з HTML-форми через об'єкт `request.form`, перевіряє заповнення обов'язкових полів і додає запис у таблицю `trips` (`INSERT INTO`), після чого перенаправляє на головну сторінку (`redirect(url_for('index'))`).
   * `@app.route('/done/<int:trip_id>')` (`toggle_done`) — змінює статус поїздки (`done`) між «заплановано» (`0`) та «відвідано» (`1`) за її ідентифікатором.
   * `@app.route('/delete/<int:trip_id>')` (`delete_trip`) — видаляє обраний запис із бази даних за допомогою SQL-команди `DELETE`.
3. **Шаблонізація (`templates/index.html`):**
   * Використано рушій шаблонів **Jinja2** (`{% for trip in trips %}`, `{% if trip['done'] %}`) для динамічного рендерингу списку подорожей, відображення статусу та генерації посилань за допомогою `url_for()`.

## 2. Контрольні запитання

### Загальне запитання (Flask)
**Запитання:** Як би ви змінили код, щоб зберігати дані завдань не в пам'яті, а в базі даних SQLite? Опишіть необхідні зміни у коді `app.py` та у структурі проєкту.

**Відповідь:**
1. **Структура проєкту:** у корені проєкту з'являється файл бази даних (наприклад, `travel_planner.db`). Глобальні змінні `tasks = []` та `task_id_counter = 0` в `app.py` видаляються, оскільки за зберігання даних та автоінкремент `id` відповідає СКБД.
2. **Зміни в `app.py`:**
   * Імпортується модуль `sqlite3`.
   * Додається функція `init_db()`, яка при старті додатку виконує запит `CREATE TABLE IF NOT EXISTS ...`.
   * У маршруті `/` замість читання списку з пам'яті виконується `SELECT * FROM ...`.
   * У маршруті `/add` виконується параметризований запит `INSERT INTO ... VALUES (?, ...)` та `conn.commit()`.
   * У маршрутах `/done/<id>` та `/delete/<id>` замість циклів по списку виконуються SQL-команди `UPDATE` та `DELETE` за умовою `WHERE id = ?`.

### Контрольне запитання (Варіант 12)
**Запитання:** Як би ви додали інтеграцію з картографічним сервісом?

**Відповідь:**
Інтеграцію з картографічним сервісом (наприклад, **Google Maps** або **OpenStreetMap / Leaflet.js**) можна реалізувати двома способами:
1. **Клієнтська інтеграція (Frontend / JavaScript):** підключити бібліотеку **Leaflet.js** із безкоштовними тайлами OpenStreetMap або **Google Maps JavaScript API** у шаблон `index.html`. При додаванні поїздки користувач може клікнути по карті для вибору координат (`latitude`, `longitude`), які зберігаються у прихованих полях форми (`<input type="hidden">`), а всі збережені маршрути відображаються у вигляді маркерів на інтерактивній карті.
2. **Серверна геокодація (Backend / Geocoding API):** при збереженні назви міста в маршруті `/add` сервер виконує HTTP-запит (через бібліотеку `requests`) до API геокодування (наприклад, Nominatim API від OpenStreetMap або Google Geocoding API), отримує точні географічні координати місця та зберігає їх у відповідних колонках бази даних SQLite.
